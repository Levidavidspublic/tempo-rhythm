## Public contract

```ts
type Research = { useWeb: boolean; thinkHard: boolean };
type Key = { conversationId: Id<"conversations">; requestId: string; replyTo: Id<"messages"> };
researchCapabilities({}): { useWeb: boolean; thinkHard: boolean };
beginReply({ conversationId, requestId, noteId?, dayStartMs?, dayEndMs?, todayDate?, research }):
  | { status: "ready"; requestId: string; replyTo: Id<"messages"> }
  | { status: "busy" | "idle" }
  | { status: "unsupported"; control: "web" | "thinkHard" };
replyWithControls(key: Key): { status: "replied" | "cancelled" | "unavailable" | "superseded" | "busy" };
cancelReply(key: Key): { status: "cancelled" | "idle" };
```

The browser persists the user message through existing `sendMessage` first, and flushes the current page before `beginReply`. `requestId` is a UUID. No API accepts client history or creates a second user message. Identical preparation repeats return the same ready key; changed context or controls under that key fail. One immutable controlled request belongs to each user message. Once cancelled or finished, that message cannot be executed again through either controlled or legacy reply. A client must not silently resend content to retry a terminal request.

Cancellation while preparation is pending must be queued in the client and applied to the returned ready key before any action launch. Cancelling a finished response is idle; cancellation of a prepared/running request removes its save claim atomically. Provider abort follows the bounded watcher, and does not promise a billing refund. The server owns approval, conversation/page ownership, current message selection and all context.
