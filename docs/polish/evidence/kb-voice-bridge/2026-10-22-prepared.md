## DECISIONS — exact schema change

Only `voiceSessions.agentBridge` is added, optional (existing leases remain valid without it):

```ts
agentBridge?: {
  version: 1;
  capabilityHash?: string;
  receipts: Array<{
    id: string;
    parentId?: string;
    inputDigest: string;
    state: "pending" | "running" | "done" | "cancelled" | "failed";
    requestId?: string;
    userMessageId?: Id<"messages">;
    assistantMessageId?: Id<"messages">;
  }>;
}
```

No new table, index, migration, backfill, env name or package. Receipts are capped at 128 with no eviction; absent bridge state stays absent until the owner requests a capability. A capability is two random UUIDs joined by a dot, returned once, never persisted raw. The purpose-bound SHA-256 digest is persisted. Stop/replacement removes its hash and cancels pending/running receipts. A lost capability response requires stopping and starting a new lease with a new clientKey; reconnect does not replay audio or functions.

The existing unrestricted `messages.toolCalls` metadata stores a server-written `voiceBridge: {sessionId, functionId}` relation alongside the existing `coachResearch` claim. This is not a schema addition. The lease contains only digests, IDs and state; canonical messages remain in the existing messages table.

Shared nonregistered coach helpers retain the authenticated send/crisis and prepare paths. Function-only mutual imports between coach and voice avoid duplicating the coach or voice budget policy; neither module invokes the other's exports during initialization. Existing typed wrappers and their signatures remain compatible.

## Frozen transport contract

Public functions require the signed-in lease owner; admission also requires current approval, paid entitlement, English voice lane, live owned conversation/page, active unexpired lease and both per-person/global minute budgets.

```ts
voice.agentCapability({sessionId}) -> {capability: string}

voice.beginAgentTurn({
  sessionId, functionId: string, receipt: string, text: string,
  noteId?: Id<"notes">,
  dayStartMs: number, dayEndMs: number, todayDate: string
}) -> {status: "ready", requestId: string, replyTo: Id<"messages">}
   | {status: "busy" | "cancelled" | "done" | "crisis"}

voice.completeAgentTurn({sessionId, functionId, requestId, replyTo})
 -> {status: "ready", assistantMessageId: Id<"messages">}
  | {status: "cancelled" | "unavailable"}

voice.cancelAgentTurn({sessionId, functionId})
 -> {status: "cancelled" | "done"}
```

The browser MUST flush the selected page first, then begin, then call the existing `coach.replyWithControls({conversationId, requestId, replyTo})`, then complete. It never calls another model. Duplicate begin while prepared returns the same ready identity; duplicate running execution returns busy. Admission and claiming are Convex mutations, so concurrent deliveries serialize against the same rows. A cancelled/failed receipt never becomes runnable again. Cancellation before admission saves no user message.

The HTTP adapter uses internal functions only after authenticating the capability:

```ts
voice.prepareAgentFunction({sessionId, capability, text, parentId?: string})
 -> {status: "ready", functionId: string, receipt: string}
  | {status: "unavailable"}

voice.canonicalAgentAnswer({sessionId, functionId, capability})
 -> {status: "ready", content: string, assistantMessageId: Id<"messages">}
  | {status: "unavailable"}
```

`sessionId` is always `Id<"voiceSessions">`. New speech is NFC-normalized, whitespace-collapsed and limited to 4,000 characters. Same normalized speech + parent reuses its bounded receipt; arbitrary HTTP stream/model fields cannot mint another turn because they are not arguments. Different speech cannot replace an outstanding receipt. After completion, a new turn needs the most recent completed receipt as parent and its exact live answer must still exist. Repeating identical speech with that new parent is a new turn. Missing/stale parent refuses new speech.

Receipt proof is a purpose-bound digest of capability hash, receipt ID and input digest; it authorizes no other lease/text. Neither callback history, instructions nor tool-result content is accepted by these functions. The eventual adapter must extract only authenticated new speech and a verified completed-parent anchor, never treat callback history as authority. If the provider body does not supply a verifiable anchor, fail closed.

`coach.saveReply` links the exact assistant ID atomically with saving. Complete and canonical-answer resolve that server relation, never a browser assistant ID or newest assistant. A later typed answer cannot be substituted. Once a newer voice receipt exists, an older callback cannot obtain its old answer for delayed speech. Deleted answers, crisis cards, stopped/revoked/expired/exhausted leases and invalid ownership are unavailable. Crisis admission bypasses an unrelated pending typed reply, ends the lease and creates only the existing fixed card; the late typed save is fenced and no voice model or TTS path is admitted. Hebrew live voice stays off.

The existing 20,000-character daily speech cap is retained. `linkBridgeAnswer` reserves the canonical answer’s exact `content.length` against all of the owner’s leases on that day in the same transaction as saving the assistant and changing running→done. Repeated completion/callback reads cannot reserve again. A failed network/audio delivery does not refund the reservation. If speech allowance is exhausted, text and its pending proposal still save, but the receipt becomes failed and both complete/canonical refuse audio. No additional schema field is needed.

Provider/model execution and late save both recheck the same voice lease. Stop/cancel clears the exact coach claim; the existing bounded cancellation watcher aborts the provider and the save mutation refuses late results. Existing proposals remain pending and retain Accept plus five-minute Undo. No auto-Accept path exists.
