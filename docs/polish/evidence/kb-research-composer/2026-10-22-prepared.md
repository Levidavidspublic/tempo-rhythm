## Behavior

- The mounted coach composer offers **Use the web**, **Think hard**, and an active **Cancel reply** action. Capability queries control availability; unavailable settings never imply research is working. Defaults leave both options off.
- Typed messages, starters and follow-ups save the user's message before preparing a controlled reply. Page context must finish saving before preparation. A failed page save retries the saved message without sending it twice.
- One UUID belongs to one prepared turn. Cancellation during preparation waits for its reply-to key and cancels before starting the action. Failed cancellation keeps the same key available; a dropped action response cancels the known server request before freeing the composer.
- Drafts belong to the account/thread/page view. A late result from another view cannot clear the current draft or release a newer request. Cancellation leaves the saved message in history. Completed controlled messages are not silently replayed through the legacy action.
- Existing voice, crisis guard, proposal Accept/Undo, source cards, Executor cards, page context and history render paths remain. Voice retains its existing guarded flow; these research options apply to typed messages and picked prompts.
- English and Hebrew copy are included. Hebrew is machine drafted for Amit's native read. Buttons use existing design tokens, native keyboard behavior and the existing touch-size token.

## Contract

`coach.researchCapabilities({}) -> { useWeb: boolean, thinkHard: boolean }`.

After `coach.sendMessage`, call `coach.beginReply({ conversationId, requestId, noteId?, dayStartMs?, dayEndMs?, todayDate?, research: { useWeb, thinkHard } })`. The ready response identifies `{ requestId, replyTo }`. `coach.replyWithControls` and `coach.cancelReply` receive the identical `{ conversationId, requestId, replyTo }` key. Busy, idle and unsupported preparation responses never execute the action. Cancel retries never send another user message or start another action.
