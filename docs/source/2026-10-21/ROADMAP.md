# Tempo Flow roadmap

Updated 2026-10-21. Documentation draft for review; implementation and live acceptance are separate.

## Verdict

Prove the core planning loop before widening the product. MVP means the minimal launch product; Gen 1 means the complete first generation. This is a consolidated scope map, not a shipping claim. Calendar commitments are UNKNOWN.

| Horizon | Outcome | Exit evidence |
|---|---|---|
| MVP | Approved sign-in, Today, Markdown pages, task/time planning, templates, contextual assistant, explicit proposals and recovery | Real accepted/reloaded results; owner isolation; safe errors; English/Hebrew; exact-revision preview proof |
| Gen 1 | Broader study, controlled memory, searchable Library, richer templates/modules, voice and native parity where their contracts are accepted | Each feature's own implementation, privacy, review and device acceptance; no inheritance from prototype counts |
| Later | Scoped notebooks/source discovery, broader connector operations, optional day context/utilities, desktop/extension and store distribution | Adopted contracts, bounded dependencies and independently demonstrated behavior |
| Held | Persona/council policy, unresolved resource retention/cleanup, semantic-memory activation, external-action reversibility | Dated owner decisions recorded in the default branch before implementation |

## MVP order

1. Reconcile the sign-in/approval order and prove an actual approved session reaches Today.
2. Establish the canonical page writer, source-safe editor, derived tasks and operation ledger.
3. Wire capture, daily planning, templates and assistant proposals through that same authority.
4. Prove reload, rejected proposal, stale save, Undo and account/object ownership boundaries.
5. Complete route-level accessibility and English/Hebrew review, then record preview acceptance.

The five-loop preview pattern is: sign in to Today; create/reload a task; create/edit/reload a template page; accept and Undo a planning proposal; save a decision card to today's page. Repeated passes must use the same final revision and target environment. A prior run report is dated evidence only.

## Gen 1 dependencies

Study remains a separate surface from Today. Source-to-study conversion is previewed and accepted; answer generation retains source grounding. Memory import depends on confirmation, attribution, deduplication and safe lifecycle operations. Search and Library depend on complete bounded traversal across their actual storage owners. Module activation depends on exact-code approval and isolation, with Plain mode and built-in fallbacks. Voice depends on the same action, cancellation and ownership semantics as text plus real device acceptance.

## Later proposals retained

Notebook Ask/Find, source viewers, summaries and study previews remain proposals behind source-term, retention and API contracts. Optional day context and utilities must be opt-in. External tools require a separate connector contract and inspectable action confirmation. A desktop shell, extension or store listing is not delivered by web or prototype coverage.
