## Open decisions and conflicts

| Question | Preserved boundary |
|---|---|
| Approval before link delivery or waiting after sign-in? | PRD and implementation order differ; do not claim either fully proven |
| Explicit acceptance versus high-confidence automatic application? | Default rules conflict; no new automatic mutation authorized |
| Raw MCP body versus safe projection? | Protected internal payloads must not leak; contract still needs reconciliation |
| Five-minute Undo, thirty-day restore, account reactivation and purge? | Separate guarantees; a reopened account does not prove restored child data |
| Resource retention versus transient imports? | Separate data classes; real activation and physical cleanup remain gated |
| Informational counts versus pressure-free habit copy? | Existing owner decision remains needed; no automatic UI-policy choice |
| Visible memory versus semantic graph activation? | Confirmation/attribution do not prove semantic-index readiness |
| External writes versus universal Undo? | Irreversible outcomes require an honest separate contract |
| Library completeness across message stores? | A list from one store cannot claim complete history |
| Native target size and accessibility thresholds? | Use the current accepted component contract and actual-device proof |
| Persona presets versus dial-only tone? | Keep persona/council work held |
| Reported validation counts from different branches? | Preserve exact environment/revision and do not add counts together |

Unknown adoption dates stay UNKNOWN. New source chronology may correct stale wording but does not grant ownership, activate a feature or authorize deployment.
