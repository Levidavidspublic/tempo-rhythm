### Rules added by the settlement

| ID | Rule |
|---|---|
| ED-01 | Live Preview is CodeMirror 6 over the exact `notes.body` text. The CodeMirror document is the body string. Decorations (hidden markers, rendered headings, lists, checkboxes, tables, links) change only how it looks, never its bytes. |
| ED-02 | Protected blocks in Live Preview. Every `valid` or `broken` segment of `base` (B-17) is one atomic replace decoration, drawn as a block widget card from the #885 catalog (TaskBlock, PageMeta, TemplateBlock, BrokenBlockCard). The cursor and the selection step over it. It never reveals its JSON: not on focus, not with the cursor on it, not in an attribute. A transaction that would change a byte inside it is dropped, unless it is a typed block operation or a B-18 removal. Protected ranges are mapped through each transaction; codec classification still happens only at commit points (B-09). A fence typed or pasted this session follows B-18a. |
| ED-03 | Classification is by the codec only (B-05). CodeMirror's Markdown parser may style prose, but it never decides what a Tempo block is, and no codec range is handed to a Markdown decoration. |
| ED-04 | Byte-exact save. An untouched page loads and saves back identical, and opening and closing it makes zero writes (B-03, RTP-A). By its API documentation (not run here), CodeMirror's default document model splits lines on CRLF, CR and LF and joins them with LF, which would rewrite a CRLF body. So the editor keeps each body's own terminators, for example by setting `EditorState.lineSeparator` to the body's terminator (EXTRAPOLATED mechanism). A body with mixed terminators is UNKNOWN until the S-07 fixture run shows that it round-trips (CG-15). The byte-exact test uses one fixture that holds every block type (page-meta, task, template, broken), mixed Hebrew and English paragraphs and a GFM table, in LF and in CRLF (BT-01). |
| ED-05 | Wiki links. `[[Title]]` in prose (not inside code) is a live link. Typing `[[` opens a picker of the owner's pages, and choosing one inserts `[[Title]]` as text. "Linked here" lists the owner's live pages whose bodies link to this page, computed from bodies. Any cache of it is a disposable index rebuilt from bodies (CORE-WEB-NOTES settlement). Which page a title resolves to when two share it, and what a rename does to links, are UNKNOWN (section 14, item 16). |
| ED-06 | Slash menu and paste. Each Text item inserts Markdown text through the span-edit path (B-02): `# `, `## `, `### `, `- `, `1. `, `- [ ] `, `> `, a code fence with no info string, `---`, and a GFM table skeleton. No slash item writes a `json tempo` info string; Tempo blocks come only from typed block operations. Pasted Markdown is inserted as text and then decorated. The plain-text clipboard flavor is used; converting pasted rich HTML is not adopted (EXTRAPOLATED). A pasted `json tempo` fence is this-session text (B-18a). |
| ED-07 | Copy. Copying or cutting a selection gives the Markdown source of its prose. A protected block inside the selection adds nothing to the clipboard (B-07, BT-03), and cut leaves it in place (B-10). The page actions Copy as Markdown and Export .md are the owner-initiated export of OD-06: they hand the owner the exact body, `json tempo` fences included, so the file re-imports losslessly. This reads decisions 1 and 7 together (EXTRAPOLATED): the JSON is never shown in the app. If Amit wants exports to replace blocks with readable Markdown instead, only this rule changes. |
| ED-08 | Direction. Every paragraph, list item, heading, blockquote, table cell and Live Preview line carries `dir="auto"` (CodeMirror's per-line text direction). Code blocks, inline code and numeric values (dates, times, durations, counts) are `ltr` (B-15). |

## 1. Summary

1. **Raw and Split are reachable without a new editor framework.** They compose #790 (PageView, a renderer) and #791 (PageEditor, segmented prose editing). Both are held and unmerged. This is segmented source editing. It is not Live Preview and it is not Rich Text, and it must not be labelled so (AE-02). Superseded 2026-10-12: the page editor is CodeMirror 6 Live Preview (ED-01), and Raw and Split are optional.
2. **Live Preview and full Rich Text need a new editor engine.** That is OD-01. Recommended default: no engine in the next-week scope. If Amit wants Live Preview, authorize a time-boxed spike of a source-as-document engine (CodeMirror 6 edits the Markdown text itself, so unedited regions cannot change; document-model engines do not). Defer full Rich Text. Superseded 2026-10-12: OD-01 is settled. CodeMirror 6 Live Preview is the editor (decision 2), and Rich Text is not adopted.
3. **The Markdown string in `notes.body` stays the only persisted representation** (AE-01). Any second persisted representation is OD-02. Recommended default: reject. Settled 2026-10-12: rejected (decision 1).
4. **Boundary hazards were reproduced on the merged codec (`packages/utils/src/blocks.ts`).** Deleting the one line break between a prose line and a following Tempo fence turns a valid block into plain visible prose. Appending text directly after a closing fence at end of body turns it into an unclosed fence that swallows the text. Typing only an unclosed `json tempo` opener in prose before an existing block pairs it with that block's closer and turns the existing block into a broken segment. Typing an unclosed raw HTML opener such as `<!--` there turns the block into visible prose (the codec's raw HTML rule, K-06). In both cases the round trip still holds, so the codec itself reports nothing. A byte-identical copy of a block pasted before it becomes the valid block and turns the original into a duplicate (BD-21, observed 2026-10-12). Section 5 (AE-04, AE-14, B-17) and section 7 (BD-01 to BD-12, BD-21) fix the rules and the tests.
5. **Candidates and licenses.** Registry licenses on 2026-10-11: MIT for react-markdown, remark-gfm, CodeMirror 6, Tiptap, Lexical, Milkdown, MDXEditor, `@uiw/react-md-editor` and `vditor`; **MPL-2.0 for `@blocknote/core` and `@blocknote/react`**. HARD_RULES section 3 lists MPL as acceptable, but MPL-2.0 is file-level copyleft, so an MPL-2.0 candidate needs the section 3 license-boundary check before admission (AE-11). That check is not done here: UNKNOWN. Some transitive packages carry other licenses: Milkdown's tree has one `(MPL-2.0 OR Apache-2.0)` package and `vditor`'s tree has an Apache-2.0 one. Plate is excluded by default because its resolved tree pulls in client-state libraries that HARD_RULES section 2 forbids (the names are in that file and are not repeated here). BlockNote's XL packages are `GPL-3.0 OR PROPRIETARY`. Blinko's editor code is GPL-3.0 and must not be copied. MDXEditor has one transitive package with no license field (UNKNOWN).
6. **The repo's component test harness cannot prove bidi, IME, selection or clipboard behavior.** Those need a real browser. Signed-in Playwright specs skip without `TEMPO_E2E_STORAGE_STATE`, so preview proof is a separate later gate.
7. **Eight later splits** are proposed in section 12 (S-01 to S-08), each at most 3 files plus 1 test, none admitted. S-08 (the oversized-body download) is the only access path for an oversized note. It depended on OD-06, whose default was adopted on 2026-10-12.

## 4. Vocabulary

### 4.1 Modes (EXTRAPOLATED definitions)

| Mode | Definition | Document the user edits | Needs a new engine |
|---|---|---|---|
| Raw | The user edits Markdown source text. | Source text | No (Tier 0 is segmented textareas plus protected block controls, #791) |
| Read | Rendered, read-only page. Block controls emit typed callbacks. | None | No (#790) |
| Split | Raw pane and Read pane over the same draft. | Source text | No (composition of #790 and #791, section 8) |
| Live Preview | One pane. The buffer is Markdown source. Syntax is rendered inline except where the cursor is. Tempo blocks are atomic widget cards that never reveal their JSON (ED-02). | Source text | CodeMirror 6, settled 2026-10-12 (ED-01) |
| Rich Text | One pane. The surface is a structured document that is serialized back to Markdown. | Structured document | Not adopted (OD-01 settled 2026-10-12) |

The distinction that decides fidelity: in Raw, Split and Live Preview the thing being edited is the source text, so an unedited region cannot change. In Rich Text the thing being edited is a document tree, and the Markdown comes from a serializer.

### 4.2 Segment terms

Prose segment: a `markdown` segment. Protected block: a `valid` or `broken` segment. Only prose segments are free text. Terms follow the codec in K-02.

### 4.3 Tiers

Tier 0: needs only merged code (including react-markdown, merged by #881 for #801) plus #790 and #791. Tier 1: the CodeMirror 6 Live Preview editor, adopted on 2026-10-12 (decision 2, S-07).

## 7. Round-trip specification and fixtures

### 7.1 Properties

| ID | Property |
|---|---|
| RTP-A | No-op: body, open in mode M, close with no edit: persisted body identical, zero write calls. |
| RTP-B | Local edit: edit inside one prose segment: the composed body differs from the original only inside that segment's span, plus at most one boundary-guard terminator (B-04). |
| RTP-C | Mode switch: body, edit in M1, switch to M2, switch back: draft identical, no write on a switch. |
| RTP-D | Reload: the saved body re-parses to the same segment kinds and spans. |
| RTP-E | Block operation: a typed block operation, including a B-18 removal, changes only that block's source (a removal deletes exactly its bytes) in the body it is applied to: the stored body for a `patchBlock`, the current draft for a whole-body write. Every other byte, unsaved prose edits included, is identical (BD-16). A B-18 removal is applied to the draft at once, so text typed while its write is in flight is kept whatever the answer. On success the block stays out of every later body (BD-17, BD-20). On failure the rollback puts back exactly its bytes, once, into the current draft, plus at most one B-04 terminator at each of its two boundaries (BD-18, BD-19). |
| RTP-F | Protected-block preservation: for any edit, either every protected block of the base body is found in `parseTempoBlocks(candidate)` at its own composed span, with the same kind, id and bytes (a copy elsewhere does not count, BD-21), or the write is refused (B-17). |

### 7.2 Synthetic constants

`TASK_A`, `TASK_B`, `META` are fences (opener line, one JSON line, closer line, each ended by LF unless a fixture says CRLF). `TASK_DUP` reuses `TASK_A`'s id.

~~~~markdown
```json tempo
{"type":"task","id":"blk_01K5F3Z8Q2C9P4Q6R8T0V2X4Z6","v":1,"data":{"title":"Email supervisor","status":"now","order":1,"inelastic":false}}
```
~~~~

- `TASK_A`: id `blk_01K5F3Z8Q2C9P4Q6R8T0V2X4Z6`, title `Email supervisor`, status `now`, order 1.
- `TASK_B`: id `blk_01K5F3Z8Q4E1N3P5R7T9V1X3Z5`, title `Second`, status `later`, order 2.
- `META`: id `blk_01K5F3Z8Q0A7M2N4P6R8T0V2X4`, type `page-meta`, data `{"pageType":"daily","date":"2026-10-11","tags":["uni"]}`.
- `TASK_DUP`: id of `TASK_A`, title `Copy`, order 3.
- `BROKEN`: a Tempo fence whose body line is `{ nope }`.
- "Opener": the line of three backticks followed by `json tempo`. "Closer": the line of three backticks.

## 8. Split View by composition of #790 and #791

### 8.1 What the two tickets give (ticket prose only, EXTRAPOLATED until merged)

- #790 PageView: renders prose and catalog blocks in source order, accepts a canonical body or validated segments, uses `dir=auto` on paragraphs, disables raw HTML and unsafe URL schemes, renders broken blocks as safe cards, does not mutate the body.
- #791 PageEditor: editable Markdown prose segments around rendered block controls, `+ Task` through the canonical codec, a save of the complete canonical body with revision and request id, draft kept on error, a stale revision surfaced without overwriting, no raw fenced-body editor.

### 8.2 Composition

Split = PageEditor (Raw presentation) next to PageView fed the editor's current draft.

| ID | Tag | Rule |
|---|---|---|
| SP-01 | AE | The editor owns the draft. PageView receives segments parsed by the shared codec from that draft. There is exactly one codec. No second parser. |
| SP-02 | AE | In Split, the preview pane is display-only for blocks. Block controls (tick, `+ Task`) live in the editor pane and in Read mode. This keeps one writer. |
| SP-03 | AE | Writes are serialized per page: a draft save and a block patch go through one in-order queue with one write in flight at a time, each carrying the revision returned by the previous one. Every whole-body write (draft save, `+ Task`, a B-18 removal and its Undo) is composed on the current draft when it leaves the queue, never on `base` alone, so a block operation never drops unsaved prose (BD-16). Any success replaces `base` (with the body a whole-body write sent, or the patched body for `patchBlock`) and never replaces the draft. Text typed while that write was in flight stays in the draft and goes out in the next save, and the re-segmentation at that commit point parses the current draft (B-09). A B-18 removal is staged in the draft at once, so every write composed after it carries it and none can bring the block back (BD-17, BD-20). A failed write stops the queue and keeps the draft. If it definitely failed and carried a staged removal, that removal is rolled back into the current draft (B-18b, BD-18, BD-19). This relies on the proposed #787 revision contract (EXTRAPOLATED). |
| SP-04 | AE | Switching among Raw, Read and Split never loses an unsaved draft and never triggers a save. |
| SP-05 | AE, EXTRAPOLATED | The preview update is deferred and low priority so typing is never blocked. No debounce value or size budget is adopted. It must be measured on a body near the 1,048,576 limit. UNKNOWN until measured. |
| SP-06 | AE, EXTRAPOLATED | Below a width breakpoint Split collapses to one pane with a Raw and Read switch. No scroll synchronization in the first slice. |
| SP-07 | AE | The mode preference is a per-device convenience stored in `localStorage` inside `try/catch`, never in Convex, never in the body. |

### 8.3 Verdict

Feasible at Tier 0, with no new editor framework, once #790 and #791 merge and the page folder is free. It needs a new split ticket for the composition (S-04) and for the gaps CG-01, CG-07 and CG-09. It is **not** live-rich editing. In Split the left pane is a source editor and the right pane is a read-only render. Calling it Live Preview or Rich Text would misstate it (AE-02). Settled 2026-10-12: the page editor is Live Preview (ED-01), and this composition is optional.

### 9.4 Fidelity expectation by engine class (EXTRAPOLATED)

- **Source-as-document engine** (CodeMirror 6 class). The edited object is the text, so unedited regions cannot change. Lossless by construction. The open work is hiding syntax, atomic protected ranges, and per-line direction.
- **Document-model engine** (ProseMirror, Lexical, Slate classes). The Markdown comes from a serializer. AST serializers commonly normalize emphasis markers, bullet markers, ordered-list numbering, table padding and alignment, hard-break style, escapes, reference-style links, HTML blocks, setext versus ATX headings, code-fence marker, thematic-break character, link title quotes, autolink brackets, entities, line endings and the final newline. This is general behavior and is **not verified for any candidate here**. AE-03 requires span-level edits so untouched segments cannot be normalized. A candidate may normalize only inside a segment the user touched, and only with OD-03 approved.

No duplicate block appears, in the editor or in the next saved body. A failure of a write that did not carry the removal (one sent before Remove, or a `patchBlock`) does not roll it back. | FT-17 | A later save never reinserts a removed block (B-02, BD-20).
