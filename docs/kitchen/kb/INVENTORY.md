## Method and meaning

Enumerated tracked TSX modules (including private named subcomponents), followed static import/re-export edges through relative paths, `@/` and `@tempo/ui`, and mapped reverse reachability to Next page/layout files. Every row names its path, component names, screen reachability, source-level v3 finding, KA owner/KB follow-up and immediate importers. Layout reachability means shared shell use, not proof of a particular render branch. Dynamic registry selection and re-export ambiguity remain UNKNOWN. Names detected from declarations are a review aid; a module's anonymous renderers are included in its row.

“Partial” is a specific source finding, not a visual verdict: a legacy utility may inherit an approved alias, and a physical property can be intentional for LTR code. “v3 source candidate” is not PASS. Contrast, actual 44 px targets, focus behavior, reduced motion and composition of one h1/main need the ticket's rendered gallery and mounted-screen checks. No screenshot, authenticated account or product code was changed for this docs inventory. Provider-only modules are N/A for visual polish but need behavioral regression coverage. Tests and helpers are listed separately so no file disappears from the census.

The 20 Oct named-import audit confirms HistoryScreen imports only CoachBubble and Pill from the primitives barrel. Button/Field/HabitRing/Ring/SoftCard/TaskRow therefore do not inherit a verified /history mount from that barrel. ScaffoldScreen imports Button/Pill/SoftCard, but no current production caller of ScaffoldScreen was found; dynamic mounts remain UNKNOWN.
