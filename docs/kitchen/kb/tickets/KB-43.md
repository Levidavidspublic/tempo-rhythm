CONTRACT:
Only the existing active legacy coach endpoints are used; no new model call path or queue table:
```ts
crisis.check // query
 ({text:string}) -> {isCrisis:boolean};
coach.sendMessage // mutation
 ({conversationId:Id<"conversations">,content:string})
 -> {success:true;crisis?:boolean};
coach.reply // action
 ({conversationId:Id<"conversations">,noteId?:Id<"notes">,
   dayStartMs?:number,dayEndMs?:number,todayDate?:string,searchOptions?:SearchOptions})
 -> {status:"replied"|"unavailable"|"idle"|"busy"|"superseded"};
```
`SearchOptions` is KB-16's exact mode/sources/domains object. On web reuse deliverCoachMessage; on native use the same guard → send → reply sequence. Content is trimmed, nonempty and at most 4000 UTF-16 units. A queue item is `{id:string, conversationId:Id<"conversations">, text:string, state:"queued"|"sending"|"sent_waiting"|"paused", options:SearchOptions}` in component memory only. At enqueue, copy and freeze the selected SearchOptions (including copied sources/domains arrays); if the composer has no selection, resolve to balanced + [web] + [] at enqueue. Pass that exact snapshot to coach.reply on dispatch and retries. Later composer changes never alter queued intent. Test enqueue, composer change, dispatch and reply retry to prove the snapshot is retained. Remember send acknowledgement before requesting reply; busy/unavailable retries reply for an acknowledged item and never sendMessage again. A network-ambiguous send pauses with an explicit review-needed state: do not automatically resend and risk duplicates. Only `replied` releases the next item. `idle` and `superseded` move the acknowledged item to `paused`, preserve its text and block automatic dispatch until explicit review; neither proves a reply completed. For `busy` or `unavailable`, keep `sent_waiting` and retry only coach.reply at 1, 2 and 4 seconds (three retries maximum per explicit attempt); after exhaustion move to `paused`. Cancel retries on unmount, account/conversation change or explicit pause. A manual retry starts a new bounded reply-only attempt and never resends an acknowledged message. Tests cover every status, exhausted retries and cancellation. Limit five unsent items per selected conversation. No automatic account-wide queue, persistent raw text, cross-tab dispatch or Agent writes. Mapped Agent chat refuses with existing legacy_chat_moved and retains unsent text for explicit copy/discard. User enqueue is consent to send that exact draft; model proposals still require Accept and five-minute Undo.
