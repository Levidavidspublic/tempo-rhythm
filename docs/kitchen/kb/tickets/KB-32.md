CONTRACT:
Exact proposed KB-31 API, extending KB-01; no new schema fields or tables.
```ts
type BulkOp = { kind:"archive"; archived:boolean } |
  { kind:"tags"; tags:string[] } | { kind:"delete" };
conversations.libraryBulk // mutation, approved owner, explicit confirmation
  ({ conversationIds: Id<"conversations">[], operation: BulkOp, requestKey: string })
  -> { affected: number; receipts: { token:string; undoUntilMs:number }[] };
conversations.libraryUndoReceipts // query, authenticated owner
  ({ paginationOpts:{cursor:string|null;numItems:number} })
  -> { page:{token:string;undoUntilMs:number;conversationIds:Id<"conversations">[]}[];
       continueCursor:string;isDone:boolean };
conversations.undoLibraryChange // KB-01; add atomic multiple-token endpoint below
  ({token:string}) -> {restored:true;conversationIds:Id<"conversations">[]};
conversations.undoLibraryBulk // mutation, approved owner
  ({tokens:string[]}) -> {restored:true;conversationIds:Id<"conversations">[]};
messages.exportPage // query, owned selection, bounded read
  ({ conversationIds:Id<"conversations">[], cursor:string|null,
     snapshot:string|null, numItems:number })
  -> { records:({kind:"conversation";id:string;title:string;createdAt:number;
                updatedAt:number;folder:string|null;tags:string[];pinnedAt:number|null;
                archivedAt:number|null} |
               {kind:"message";id:string;conversationId:string;
                role:"user"|"assistant";content:string;createdAt:number;
                sources:{title:string;site:string;url:string}[]})[];
       cursor:string|null;snapshot:string;isDone:boolean };
```
Select 1–50 distinct owned conversation IDs. Request keys are 1–128 ASCII letters/digits/_/-. All bulk ownership, receipt-capacity and operation validation happens before any write; a foreign/missing ID rejects the whole transaction with unavailable. Tags replace selected chats' tag sets only after a preview. Archive and delete are explicit user actions; AI-originated requests must use the existing proposal path instead. Delete tombstones parent conversations only; preserve each message and old deletion timestamp. Independent per-chat receipts are exposed, and undoLibraryBulk atomically checks every supplied token before restoring any. Server clock five-minute Undo and idempotency follow KB-01; later unrelated writes must not be overwritten.

Export is read-only and uses an allowlist, never raw Doc serialization: no userId, system messages, toolCalls, Agent IDs, provider errors, modelUsed, secrets, internal receipts or third-party raw source text. A snapshot binds owner, ordered selected IDs and each chat updatedAt plus newest live message boundary. Each page revalidates ownership and version; an edit/delete invalidates with `ConvexError({code:"export_changed"})`. `numItems` is 1–100; at most 100 indexed messages/25 chats scanned per invocation; include continuation for empty slices, no total truncation. Output conversation header once then messages oldest first by createdAt/ID. A mapped Agent chat returns `export_unsupported` before emitting any export; do not silently omit new Agent content. Other codes: unavailable, invalid_cursor, invalid_selection, invalid_request_key, invalid_tag, receipt_limit, conflict, expired. No server file storage, email, scheduling or new dependency.

Markdown and JSON formatting is client-side. JSON is `{version:1, exportedAt:string, conversations:Array<{id,title,createdAt,updatedAt,folder,tags,pinnedAt,archivedAt,messages:Array<{id,role,content,createdAt,sources}>}>}` with all timestamps ISO UTC strings and nulls retained. Markdown has one title per conversation, timestamped role headings and a numbered source appendix per assistant message. Both formats preserve Unicode and escape structural Markdown when generating headings, and warn that downloaded/shared copies cannot be recalled by Undo.
