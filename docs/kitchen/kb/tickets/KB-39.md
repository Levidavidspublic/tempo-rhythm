CONTRACT:
Exact proposed KB-01 API (all timestamps are epoch milliseconds; IDs are Convex IDs). These are additions, not claims that the endpoints already exist.
```ts
type PageArgs = { cursor: string | null; numItems: number }; // 1..50
 type Filters = { fromMs?: number; beforeMs?: number; folder?: string;
  tags?: string[]; pinned?: boolean; archive?: "active" | "archived" | "all" };
type ChatRow = { id: Id<"conversations">; title: string; createdAt: number;
  updatedAt: number; folder: string | null; pinnedAt: number | null;
  tags: string[]; archivedAt: number | null; chatMode: "legacy" | "agent" };
type Source = { title: string; site: string; url: string };
type MessageRow = { id: Id<"messages">; conversationId: Id<"conversations">;
  role: "user" | "assistant"; content: string; createdAt: number; sources: Source[] };
type Receipt = { token: string; undoUntilMs: number };
conversations.libraryPage // query
  ({ filters: Filters, paginationOpts: PageArgs })
  -> { page: ChatRow[]; continueCursor: string; isDone: boolean };
messages.historyPage // query, newest first; UI reverses for reading
  ({ conversationId: Id<"conversations">, paginationOpts: PageArgs })
  -> { page: MessageRow[]; continueCursor: string; isDone: boolean;
       coverage: "complete" | "legacy_only" };
messages.searchPage // query, literal NFC + case-folded substring over title/content
  ({ query: string, filters: Filters, paginationOpts: PageArgs })
  -> { page: { chat: ChatRow; message: MessageRow | null;
              matchStart: number; matchEnd: number; historyCursor: string | null }[];
       continueCursor: string; isDone: boolean; coverage: "complete" | "legacy_only" };
conversations.setLibraryMetadata // mutation, explicit user edit only
  ({ conversationId: Id<"conversations">, tags?: string[], archived?: boolean, requestKey: string })
  -> Receipt & { conversation: ChatRow };
conversations.undoLibraryChange // mutation
  ({ token: string }) -> { restored: true; conversationIds: Id<"conversations">[] };
```
Schema additions on `conversations` only: `tags?: string[]`, `archivedAt?: number`, `libraryRevision?: number`, `libraryReceipts?: Array<{ token:string; requestKey:string; appliedRevision:number; undoUntilMs:number; previous:{tags?:string[];archivedAt?:number;deletedAt?:number}; result:{tags?:string[];archivedAt?:number;deletedAt?:number} }>`. Keep KA `folder` and `pinnedAt`. Existing owner indexes suffice; no new table. At most 32 unexpired receipts per chat; reject another edit with `receipt_limit` rather than losing Undo. Remove expired receipts only on the next explicit metadata write. Store no transcript or provider text in receipts. A token is a random opaque identifier; ownership is checked independently, never inferred from knowing the token. Scope ownership and `updatedAt` changes apply to every write.

Reads require an authenticated owner; writes also require approval. `ConvexError({code})` codes: `unavailable`, `invalid_filter`, `invalid_cursor`, `invalid_tag`, `invalid_request_key`, `expired`, `conflict`, `receipt_limit`. An unknown or foreign ID/token gets the same `unavailable`. Tags: Unicode NFC, trim/collapse spaces, 1–32 Unicode code points, max 10, case-insensitive dedupe retaining the first display spelling, no control characters; all selected tags must match. Folder equality follows KA-01. Date range means `updatedAt >= fromMs && updatedAt < beforeMs`. Default archive is active; deleted chats never appear. Existing conversations.list({}) keeps its public return shape but omits archived rows, so archived chats also leave the active coach column. conversations.get remains owner-readable for an archived chat; Library archive filters can reopen it. Empty chats are included, regardless of timestamps.

Pagination is a server-validated cursor containing version, owner binding, filter/query fingerprint and owner-conversation/message traversal positions; tampering cannot bypass ownership because each resumed record is checked again. Every query scans at most 100 indexed messages and 25 owner-indexed conversations per invocation, returns up to numItems, and can return an empty page with a continuation. Continue until isDone; never silently cap lifetime search at 200 chats or 80 messages. Offset ranges are half-open UTF-16 indexes in the original returned text: `message.content` for message hits and `chat.title` for title hits (`message:null`). Maintain a mapping through NFC normalization and full case folding so expanding folds such as ß→ss and combining sequences still highlight the complete original span; never return normalized-string offsets. `historyCursor` opens a page containing the hit. Use indexed owner/parent reads, not a table-wide collect. Sort chats by updatedAt descending with ID tie-break and messages by createdAt/ID. Cursor invalidation reports invalid_cursor rather than dropping hits silently after a changed filter.

Undo uses server time: valid through `undoUntilMs = committedAt + 300000`; each receipt contains the previous field values, and restoration checks that its result values/revision still match. Do not overwrite an intervening metadata change. Repeated requestKey with identical arguments returns the original receipt; a different payload with that key is conflict. Keep non-KB fields intact.

Mapped Agent conversations stay listed. Existing `messages` remain readable, but `coverage:legacy_only` explicitly states that this checkout has no public Agent transcript reader. UI shows the limitation and does not claim completeness; implement neither an Agent migration nor new Agent writes. Full coverage is required for the active legacy coach/search path.
